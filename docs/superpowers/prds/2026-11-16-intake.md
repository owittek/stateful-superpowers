# Intake: nothing found mid-task gets lost — PRD

## Problem

Feature work keeps surfacing tangents: drift from a convention, a small bug next
door, an improvement that should be backported, handoff leftovers. Today the
user either chases them (derailing the feature) or keeps them in their head or
in agent memory, where they get lost. The overview of open follow-ups is gone.

The tracker bridge (`docs/superpowers/specs/2026-10-04-tracker-bridge-design.md`,
spec issue #10) builds the substrate, but its scope is spec → tickets. Its own
artifact model promises "an inbox for ideas and bugs that are not specs yet",
and nothing in it creates one: `register-parent` requires a spec path, the
ticket template requires a `## Spec` pointer, there is no search, and triage is
deferred.

## Success criteria

- A follow-up found mid-task is parked in one step, without leaving the current
  task, and survives the session.
- Parking the same thing twice doesn't create a second ticket.
- "What's open?" is one query; a cleanup session picks parked items up through
  the existing pickup runner.
- Clean repos (no tracker config) behave exactly as today.
- ADR 0002 holds: the tracker holds graph and state, never content.

## Features, in build order

1. **Refresh `next`.** Rebase onto `main` (14 commits behind at time of
   writing). Land ticket #11 (local adapter, done in its worktree). Re-place the
   brainstorming seam edits — upstream v7 brainstorming has no numbered steps.
   Fix the version clash (`main` already ships 0.9.0). Drop wayfinder's
   dependency on the removed `prototype` skill.
2. **Intake.** Tickets without a spec: a standing parent per kind, a ticket body
   whose pointer is optional or points at a non-spec source, a `find` op for
   dedupe, and a "park this" step any skill can call mid-task (SDD, the
   reviewer, finishing, handoff). Light triage: group related parks, mark stale.
   Needs its own design (brainstorming).
3. **Pickup for cleanup sessions.** `frontier` + `picking-up-ticket` from the
   tracker bridge spec (#13, #15, #16), adjusted for spec-less tickets.
4. **Spec slicing.** `publishing-tickets` and brainstorming's closing offer
   (#14) — the rest of the tracker bridge. Least urgent for this problem.

The design-consistency initiative
(`docs/superpowers/prds/2026-11-16-design-consistency.md`) is the first
automated producer of parked tickets and depends on feature 2.

## Open for the intake design

- Standing parent per kind vs parentless tickets.
- Where a parked ticket's content lives when there is no spec (ticket body only,
  or a committed note).
- Which skills park automatically vs offer to park.
- How much triage is in scope before it becomes its own feature.
